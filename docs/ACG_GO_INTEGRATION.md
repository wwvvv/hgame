# ADR：acg-go 主站 + HGAME 游戏中心副页

日期：2026-10-01。状态：用户确认，P0 实施已提交功能分支，尚未生产部署。

## 决策

acg-go 保留首页与社区，增加 `/games` 入口。hgame 不作为首页或独立商店，不建设双站SSO，不新增第二套账号、后台和交易账本。

这是对 2026-09-30 独立 Next.js 网站方案的更新，不删除历史代码和文档。旧架构、API、数据模型、路线图与本决策冲突时，以本文为准。

## 仓库职责

acg-go：React Router 玩家页面、Go/Gin游戏服务、共享原账号与后台。正式订单和购买权益以后也由这一业务后端管理，前端不直写商业表。

hgame：本地 Skill、模板、manifest/发行包契约与校验器。原 `src/` Next.js 页面留作样板，不再投入独立网站的账号和收费开发。不复制 acg-go 私有代码至本公开仓库。

运行层：已审核游戏在独立来源执行，游戏包不得接触社区Cookie、账号令牌或支付凭据。

## 用户路径

社区首页 → 游戏中心 → 游戏详情 → 免费试玩 → 后续完整购买 → 我的游戏 → 社区讨论。

首发作品由运营方统一上架；创作者本地使用 Skill 和固定模板制作，不开发线上生成工作台、公众自由上传或自动分账。社区积分与游戏购买权益分开，私人购买/游玩记录不自动公开。

## P0 已提交

[acg-go PR #38](https://github.com/wwvvv/acg-go/pull/38)：默认关闭的 `/games` 目录/筛选/分页、详情、隔离技术试玩、共享账号的游戏库说明、制作指南与站长只读配置页。

目录临时读取运营方配置 JSON；不把它称为已经实现的上传审核/版本数据库。运行 URL 仅来自显式精确白名单；默认不支持完整版。由于年龄保障尚未实现，受限内容不经自报年龄开放。

P0 不改生产部署、原首页、原社区数据或数据库迁移。本仓此配套更新只修改定位文档，不迁移旧代码或改变Skill工具能力。

## P1/P2后续开发

1. P0通过整仓SSR/SPA构建、Go编译、浏览器和账号/帖子/网盘回归后，再决定合并。
2. 实现Work/Release、原后台作品CRUD、审核记录、版本回滚和内容撤销；游戏与社区讨论先采用简单关联。
3. 实现订单、支付验签/幂等、退款、Entitlement和受控资源；按真实业务完成年龄/地区条件与服务商验收。
4. 固定首个真正可玩的引擎模板，测试Demo到Full存档迁移。没有跨域持久化验收前，不宣称无缝进度。
5. 有真实业务需求后才加会员库、作者自助投稿和结算，不提前扩展成大型平台。

## 契约适配

本仓 game-manifest 是作者交付元信息，acg-go P0 catalog.local.example.json 是运营演示目录，两者不同。未来导入服务读取通过审核的发行包，生成目录和不可变版本记录；不要求作者手工维护两套项目，也不直接把整包复制到主站 `/res`。

引擎和网站解耦：游戏继续按原引擎构建，平台管理发行版本与访问权。Skill不处理生产支付、不自动发布，不可因用户一句“已购买”而解锁文件。

## 验证状态

acg-go P0的核心Go标准库/race测试、前端纯函数及结构检查已执行；完整验证见其 PR 与 docs/game-center-status.md。本仓旧 STATUS.md 中的33项核心测试记录属于历史提交，不能转算为新模块的全量验收。

本次不合并未通过CI的功能代码、不删除hgame仓库、不部署公网、不启用真实收款。后续变更应保持“一主站、一副页、一套账号与后台”的边界。
